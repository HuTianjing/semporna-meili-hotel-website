# 查询与预定策划 — Booking & Reservations

> 路由：`/booking`
> 叙事逻辑：**管家式旅程叙事**，而非 OTA 查询流程。访客先确认向往，再自然进入预订意图。
> 目标：让访客在完成预订前，已经在脑中经历了一次完整的抵达体验。

## 技术开发说明

| 功能 | 实现方式 | 备注 |
|------|----------|------|
| 预订查询栏 sticky | CSS `position: sticky; top: 0; z-index` | 与 Header 层级协调 |
| 日期选择器 | 推荐使用 `react-day-picker` 或 `@headlessui` | 样式遵循设计 Token |
| 套餐下拉 | 原生 `<select>` + 自定义样式，或 `@headlessui/listbox` | 无障碍支持 |
| Accordion | `@headlessui/disclosure` 或 Framer Motion `AnimatePresence` | 保持动效一致性 |
| WhatsApp 跳转 | `https://wa.me/60112780399?text=...` 预填消息 | 参数由前端拼接 |
| 四步旅程图 | Framer Motion stagger 入场动画 | 参照 UI规范 5.3 |
| 房态查询后端 | 预留 API 接口，初期表单提交触发 WhatsApp 预填 | 后续接入 HMS/OTA API |
| 在线支付 | 预留支付组件位置，初期引导 WhatsApp 确认后转账 | 后续接入 Stripe / 本地支付网关 |
